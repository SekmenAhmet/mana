# mana v2 — Implementation Plan

**Date:** 2026-08-15
**Spec:** `docs/superpowers/specs/2026-08-15-mana-v2-design.md`
**Method:** TDD per task; every phase ends on a milestone that runs against a
real CLI. v1's core failure was shipping five phases that had never executed
end-to-end once — every phase here closes on a real run, not on green fakes.

Ordering rationale: the sub-agent pipeline comes before the PM because it has
no protocol risk (bare spawn) and it is the half that produces observable
value (counters, verdicts). The PM path then plugs into something already
proven. Universality (ACP, sentinel) comes only after one full loop works with
one CLI.

---

## Phase 0 — Foundations (catalogue, formats)

### 0.1 Catalogue module
- New `src/catalog/` — serde structs for the v2 schema (`schema = 1`), TOML
  parsing, placeholder substitution (`{model}`, `{prompt}`, `{config_path}`,
  `{cwd}` → argv arrays, no shell), local-override loading
  (`~/.mana/catalog.local.toml`, wholesale entry replacement).
- `catalog/claude.toml` + `catalog/agy.toml` (contents from spec §7),
  embedded with `include_str!`; a unit test parses every embedded file so a
  malformed catalogue fails `cargo test` — this is the build-time gate.
- Done when: `Catalog::load()` returns validated entries; an override file
  replaces an entry; a bad TOML fails the build, not the user.

### 0.2 Config migration YAML → TOML
- `~/.mana/config.toml` becomes canonical (matches the original managent
  spec). On load, if only `config.yaml` exists, migrate it once and say so.
- Remove `serde_yaml` from every non-legacy path (it is archived upstream).
- Done when: install/doctor/uninstall round-trip on TOML; migration test.

### 0.3 State files v2
- `subagent-lock.yaml` → `subagents.jsonl`, one record per dispatch, now with
  `pid` (unblocks `mana ps`/`mana kill` later). Single writer: mana — the
  read-modify-write race dies with the YAML map.
- Log schema: OTEL GenAI field names (`gen_ai.usage.*`,
  `gen_ai.client.operation.duration`); per-(CLI × model) counter store
  (`counters.jsonl` or derived from logs — derive first, materialize only if
  slow).
- Done when: log/lock round-trip tests on the new schema.

**Milestone 0:** `cargo test` green with the catalogue embedded and validated.

## Phase 1 — Sub-agent pipeline (no protocol, real value)

### 1.1 Plain-process spawner
- Replace PTY spawning for sub-agents with `std::process::Command` (headless
  `-p` modes are built for pipes). `portable-pty` leaves the tree unless the
  PM drivers prove they need it (they shouldn't — stream/ACP/oneshot are all
  stdio).
- Argv built purely from catalogue templates. Timeout, kill-on-drop,
  platform-conditional process groups (spec'd in the old roadmap).
- Done when: spawner tests run a fake script cross-platform; no CLI name
  appears in the module.

### 1.2 Worktree manager
- One worktree + branch per task under `~/.mana/worktrees/<project>/<task>`
  (short paths — Windows 260-char hazard), created from the project repo;
  capture `base_ref`; set a local git identity (`mana <mana@local>`) so
  executor commits succeed; `git worktree prune` + forced cleanup on task end
  (managent hit stale locks — not optional).
- Write roles refuse dispatch on non-git projects with the exact message from
  the spec; read roles bypass worktrees entirely.
- Done when: create → commit inside → diff visible → cleanup leaves no lock;
  non-git refusal test.

### 1.3 Executor dispatch + observation
- `dispatch(task, role=executor, cli×model)`: fill `assets/roles/executor.md`
  placeholders, spawn in worktree, observe: exit code, duration, files
  modified (existing watcher, noise-filtered), stderr/stdout matched against
  the catalogue's ordered failure signatures → `quota_exhausted` etc. →
  cooldown on the right pool (`pool_scope` respected). Append log + counters.
- Done when: fake-CLI tests cover success, quota-signature match → cooldown,
  timeout; then **one real run** with claude on a trivial task in this repo's
  scratch project.

> **Amendment (2026-08-18, #184):** "files modified (existing watcher,
> noise-filtered)" never shipped, and the "existing watcher" this task
> pointed at was v1 code the 4.5 kill sweep later removed — there is no
> filesystem-watch dependency in `Cargo.toml` today. What `observe` actually
> appends (`ExitEntry`, `src/log.rs`): exit code, duration
> (`gen_ai.client.operation.duration`), and failure signatures matched
> against the catalogue's ordered list. File capture needs a watcher (a new
> dependency) plus a noise filter (a judgment call) and stays open for v3 —
> it was not part of what this milestone delivered.

### 1.4 Reviewer dispatch + verdicts
- Same dispatch path, `assets/roles/reviewer.md`, `{base_ref}` +
  `{review_path}` filled; parse verdict JSON (`verdict`, `attribution`,
  `issues[]`); malformed → one corrective re-prompt, then hard-fail the
  review. Counters: only `attribution: code` rejections count against the
  model.
- Rewrite `review.rs` around the JSON contract (the markdown parser dies).
- Done when: parse/attribution/retry tests; real run: claude executor + claude
  reviewer on one task, verdict lands.

**Milestone 1 (the v1 debt paid):** a dev command (`mana dev run-task <file>`)
drives task → executor → reviewer → verdict end-to-end against real claude,
and `~/.mana/projects/<p>/` is no longer empty. Counters visible.

## Phase 2 — PM path with claude (stream driver + MCP)

### 2.1 `mana mcp-server`
- Hidden subcommand speaking MCP over stdio (evaluate `rmcp` vs
  `rust-mcp-sdk` at implementation time; pick the maintained one). Tools:
  `create_task`, `launch_subagent` (model **or** `cost_class` — resolver =
  cheapest available by counters + cooldowns, deterministic, unit-tested),
  `get_review`, `list_agents` (catalogue ∩ installed ∩ counters, per
  (CLI × model)). State lives in `~/.mana/projects/<p>/` — the server is
  stateless between calls.
- Registered into the PM via the catalogue's `mcp_args` template with
  `{config_path}` pointing at a mana-written MCP config using
  `current_exe()` — the `$PATH` blocker dies here.
- Done when: tools callable via a raw MCP client in tests; resolver picks
  cheapest, skips cooldowns, errors with valid ids on unknown model.

### 2.2 Stream driver (PM transport #1)
- Persistent child (`stream` driver): spawn from catalogue args, write user
  turns as stream-json, read events, apply `[pm.events]` JSONPaths
  (`serde_json_path`) → `text` to chat, `usage` to enrichment. Unmatched
  events → raw-line fallback (visible degradation). PM process death →
  detected, loop ends cleanly (v1 zombie bug).
- Done when: driver tested against recorded claude transcripts (goldens in
  `catalog/goldens/claude/`); session continuity verified live (probe from
  2026-08-15 becomes a test script).

### 2.3 Role injection + launch flow
- `mana launch <cli>`: resolve catalogue entry → write
  `assets/roles/pm/SKILL.md` to the first existing `skills.dirs` path
  (create if configured) → start driver → send activation message → attach
  MCP per catalogue.
- PM permission strategy: per-catalogue field (e.g. claude:
  `--allowedTools "mcp__mana__*,Read,Grep,Glob"`) so the PM mechanically
  cannot write code. **Open detail from spec §11 — resolve here.**
- Done when: `mana launch claude` reaches an interactive PM that can call
  `list_agents` for real.

### 2.4 TUI v2
- Chat pane renders PM `text` events + user input line; graph pane rebuilt
  from counters/lock (event-driven refresh, not per-frame re-parse of every
  jsonl — v1's 20 fps re-read dies). Kill: `intercept_subagent_launches`,
  `pty_listener::extract_commands`, `App::chat_lines` unbounded growth
  (ring buffer).
- Done when: TestBackend snapshots for both panes; manual QA checklist
  rewritten for v2 flow.

**Milestone 2:** full loop — user asks in mana's TUI, claude-PM creates tasks,
dispatches to a cheap model, reviewer validates, graph shows ✅ — one command:
`mana launch claude`.

## Phase 3 — Universality (any PM)

### 3.1 ACP driver
- Evaluate Zed's `agent-client-protocol` Rust crate (verify name/maintenance
  at implementation); implement Client side: `initialize`, `session/new`
  (with `mcpServers` — conformance-test per CLI, a known-uneven area),
  `session/prompt`, render `session/update`, surface
  `session/request_permission` as a TUI dialog.
- Done when: driver passes against one real ACP agent (`copilot --acp` or
  `opencode acp`); catalogue entries for copilot/opencode/gemini gain
  `driver = "acp"`.

### 3.2 oneshot-continue driver + sentinel channel
- Driver: process per turn from `first_args`/`continue_args`; verify agy's
  `--continue` actually preserves context across print calls (open item —
  test costs a few agy requests, budget it).
- Sentinel: parse fenced ```mana blocks from PM text (structured stream, not
  rendered TUI — the v1 scraping failure mode does not apply); validate
  against the same tool schemas; malformed → one corrective message.
- Done when: agy runs as PM end-to-end, tools flowing over sentinel.

### 3.3 Catalogue CI
- Golden transcripts per CLI replayed against `[pm.events]` in CI; schema
  validation job; the catalogue pitfalls learned this session recorded as
  `notes` (never pass `--tools ""` to claude — 167k cold-cache context).

**Milestone 3:** the PM role demonstrably runs on ≥3 different CLIs unchanged
except catalogue data.

## Phase 4 — Ops & polish

- 4.1 Release automation: release-plz (batched Release PR) + cargo-dist
  5-target matrix replacing the hand-written `release.yml`; `self_update`
  client keeps working; soft update check at startup.
- 4.2 `mana ps` / `mana kill` on the new pid-bearing lock.
- 4.3 `mana doctor` v2: catalogue age, per-CLI capability report (driver,
  channel, degradations), stale-worktree detection.
- 4.4 Role-text hardening: run the three `assets/roles/` texts through the
  skill-creator eval loop; iterate on real transcripts.
- 4.5 Kill sweep: delete every dead module (`pty_listener`, old prompts,
  PTY chat pane, `serde_yaml`), rewrite README + manual QA for v2.

## Out of scope for v2
Runtime isolation beyond worktrees (containers), remote catalogue fetch,
OTEL export backend, `mana status` self-reporting, Windows CI runners
(unit-level `#[cfg(windows)]` only; e2e stays a listed risk).
